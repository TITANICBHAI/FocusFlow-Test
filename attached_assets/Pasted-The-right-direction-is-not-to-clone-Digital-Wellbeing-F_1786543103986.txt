The right direction is not to clone Digital Wellbeing. FocusFlow should combine:

What time was spent + what the user intended + what FocusFlow successfully defended.

What exists today
Stats and Reports already cover:

Focus minutes
Completed/skipped/overdue tasks
Streaks and milestones
Blocked-app attempts
Override counts
Weekly/all-time focus history
What is missing is observed device/app usage. The existing UsageStatsModule only checks Usage Access and detects the current foreground app; it does not yet return daily app usage totals.

Recommended product concept
1. Device Time
Use Android UsageStats to show actual foreground time:

Total device time
Top apps by minutes
App launch/open count
Daily and weekly trends
This should be labeled as observed device time, not productivity time.

2. Focus Time
Continue using the existing FocusFlow database:

Actual focus-session minutes
Completed focus sessions
Planned vs completed focus time
Focus streak
3. FocusFlow Impact
This is the advantage over Digital Wellbeing:

Blocked attempts
Most resisted app
Overrides during focus
Distraction attempts per focus hour
Focus sessions protected by enforcement
VPN-blocked activity where available
We should avoid claiming “you saved 3 hours” from blocked attempts because an attempted app opening does not tell us how long the user would have stayed there.
