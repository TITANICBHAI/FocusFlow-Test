Found the exact cause. It's one line.

`useFocusEffect`'s callback has `state.tasks` in its dependency array (line 143). Every time `state.tasks` changes, React treats it as a new callback, runs the cleanup (clears the timer, sets `mounted = false`), then immediately re-runs the subscribe (new `mounted = true`, calls `refresh(true)`, starts a new timer).

`state.tasks` changes every time `refreshTasks()` is dispatched. And `refreshTasks()` fires every time the app comes back to the foreground — AppContext has an `AppState` listener that calls it on every `active` transition (line 338). So your exact scenario:

- You're on active.tsx, the 5-second timer is running.
- You switch apps → `AppState` goes to background. Timer is still running.
- You come back → `AppState` fires `active` → `refreshTasks()` → `SET_TASKS` dispatched → `state.tasks` reference changes → `useFocusEffect` cleanup runs (clears timer) → immediately re-subscribes → fires `refresh(true)` → 3 concurrent DB calls in flight.
- But the DB calls from the **last timer tick** before the re-subscribe are still in flight, because `mounted = false` only stops the state update, not the pending promise.
- Switch again. Repeat. After 3-4 switches you have 9-12 concurrent DB reads all holding WAL locks simultaneously.
- That's the `database table is locked` line at 07:06:31. Five minutes later the DB handle is dead.

The fix is one dependency removal. The only reason `state.tasks` is in the array is this single line inside the callback:

```typescript
const total = state.tasks.filter(
  (task) => dayjs(task.startTime).format('YYYY-MM-DD') === todayKey
).length;
```

Move that computation outside the `useFocusEffect` using a ref:

```typescript
const tasksRef = useRef(state.tasks);
useEffect(() => { tasksRef.current = state.tasks; });
```

Then inside the callback use `tasksRef.current.filter(...)` and drop `state.tasks` from the dependency array. The callback becomes `[refreshLiveData]` only, which is stable (`useCallback` with `[]`). The `useFocusEffect` now subscribes once per screen focus event, not once per task update.

While you're there, add a ref guard against overlapping refreshes:

```typescript
const refreshInFlight = useRef(false);
const refresh = (force = false) => {
  if (refreshInFlight.current) return;
  refreshInFlight.current = true;
  void refreshLiveData(force);
  void (async () => {
    try { ...DB calls... }
    catch { ... }
    finally { refreshInFlight.current = false; }
  })();
};
```

That's it. Two changes in `active.tsx`, nothing else. The DB corruption and brown screen are downstream symptoms of this one re-subscribe loop flooding the WAL.
