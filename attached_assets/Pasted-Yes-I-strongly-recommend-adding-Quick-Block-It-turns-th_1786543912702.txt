Recommended behavior
When the user sees an app in:

Top screen-time apps
Most tempting apps
Distractions blocked
Recent app usage
show a small shield action:

Quick Block

Tapping it should open a two-choice action sheet:

Block temporarily
Uses the existing Standalone Block system.

Presets:

1 hour
Until tonight
Until tomorrow morning
Custom duration
This is best for apps the user wants to control during a specific period.

Block always
Adds the app to the existing Always-On App Block List.

Copy:

Block this app 24/7 until you remove it from Always-On.

Removing it should continue to use the existing defense-password protection.

Important: do not create a third block list
Quick Block should only be a shortcut into the two existing systems:

Quick Block → Standalone Block
Quick Block → Always-On Block List

No separate Quick Block storage should be created.

Where it should appear
Reports
Make it more visible because Reports is action-oriented:

Instagram        48m     [Quick Block]
YouTube          41m     [Quick Block]

For apps already blocked:

Instagram        14 blocked attempts
Blocked until 8:00 PM

or:

Always-On blocked

Stats
Keep the interface cleaner. Show Quick Block only when the user taps an app row or opens an app detail action sheet, rather than putting a button on every row.

Avoid confusing states
The action should change based on the app’s current status:

Current state	Display
Not blocked	Quick Block
Standalone blocked	Blocked until 8:00 PM
Always-On blocked	Always-On blocked
Both lists	Always-On + temporary block
System-protected app	No block action
The existing protected-app rules must be reused so users cannot Quick Block launchers, System UI, phone services, or FocusFlow itself.

Important existing behavior to handle
The app currently has an autoCopyToAlwaysOn setting. When enabled, a Standalone Block can temporarily copy apps into the Always-On list and remove them after expiry.

That can be confusing for a Quick Block action. I recommend:

Quick Block → Temporary should remain temporary and not silently become Always-On.
Quick Block → Always should be the only action that intentionally adds to Always-On.
Existing autoCopyToAlwaysOn behavior can remain available in the advanced Standalone settings, but Quick Block should clearly explain what will happen.
Best product wording
Use:

Quick Block

Then:

Block for a while
Temporary protection with an expiry
Block always
Keep this app blocked 24/7

Avoid making “Always-On” sound like a dangerous permanent action. The user can still remove it later, with the existing defense-password rules.
