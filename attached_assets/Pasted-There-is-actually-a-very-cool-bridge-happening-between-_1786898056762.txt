There is actually a very cool bridge happening between the native Android Kotlin code and the React Native UI. Here is how it works and where the files are located:
1. The Visual UI (React Native)
File: artifacts/focusflow/src/components/BlockedAppOverlay.tsx
This file contains the exact red UI you see in the screenshot. It is a React Native <Modal> that pops up with the "APP BLOCKED" text, the red ban icon, and the "FocusFlow is protecting your focus" message.
It listens for a variable called focusViolationApp to know when to show up, and which package name to display (like com.android.fmradio).
2. The Native Detection Engine (Kotlin)
File: artifacts/focusflow/android-native/app/src/main/java/com/tbtechs/focusflow/services/AppBlockerAccessibilityService.kt
This is the deep system-level Android code that runs invisibly in the background.
When you try to open an app (like the FM Radio), this Kotlin service detects it. If the app is on your blocklist, it immediately:
Kills the blocked app's network access.
Sends an APP_BLOCKED broadcast event to the system.
Launches a native overlay or pushes the FocusFlow app to the front.
3. The Bridge (React Context)
File: artifacts/focusflow/src/context/AppContext.tsx
This file acts as the middleman. It listens for the APP_BLOCKED event coming from the Kotlin background service:
code
TypeScript
// Listens to the Kotlin Accessibility Service
const unsubAppBlocked = EventBridge.subscribe('APP_BLOCKED', (event) => {
  // Tells the React Native UI to trigger the red BlockedAppOverlay
  dispatch({ type: 'SET_FOCUS_VIOLATION', payload: event.blockedApp ?? null });
});
Summary of the flow:
You open a blocked app → Kotlin detects it and blocks it → Kotlin sends an event to React Native → React Native (AppContext) updates the state → React Native (BlockedAppOverlay) renders the red screen over the screen.
